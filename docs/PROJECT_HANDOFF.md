# Project handoff

Checkpoint of the DoIC MUJ site so another device can clone it and continue.

Remote: `https://github.com/FrostXMello/isc-doic-muj-dashboard` (branch `main`). Pushes to `main` auto-deploy to the Vercel project `isc-doic-muj-dashboard` (https://isc-doic-muj-dashboard.vercel.app).

## Current state

Implemented:

- Public site: homepage with the globe, partner directory (`/partners`, `/partners/[slug]`), opportunities, programmes, student-portal orientation, about, privacy, terms. Reads `src/lib/data.ts` only; unchanged by the backend work.
- Internal Portal at `/internal`: dashboard, institutions, agreements (MoUs), programme offerings, opportunities, activities, documents, reports. Reads through the repository layer in `src/lib/internal/data/`.
- Supabase backend foundation: schema, RLS, storage bucket, seeds, and RLS tests in `supabase/` (see Backend), applied to the hosted project `oqmwrifysignwmgxiecd`.

Not implemented, on purpose:

- Sign-in UI, write actions, uploads, and application forms.
- Official MOU, agreement, availability, or contact data. All non-directory records are fictional samples.

## Backend (Supabase)

| Path | Contents |
| --- | --- |
| `supabase/config.toml` | Local stack config (`npx supabase start`) |
| `supabase/migrations/` | Schema, triggers, RLS policies, storage bucket + policies |
| `supabase/seeds/` | Local-dev seeds, generated by `npm run db:seed:generate` from the TS seed modules |
| `supabase/tests/database/rls.test.sql` | pgTAP RLS tests (`npx supabase test db`) |

**Roles** (`public.app_role`): `student`, `isc_team`, `doic_admin`, `leadership`. Grants live in `public.user_roles`; only `doic_admin` can write it, and an admin cannot remove their own admin role. Policies call SECURITY DEFINER helpers with a fixed `search_path`, kept in the `private` schema so they are not exposed as REST RPCs: `private.has_role()`, `has_any_role()`, `current_app_roles()`, `is_internal()`, `can_edit_internal()`, `is_doic_admin()`. `user_metadata` is never used for authorisation. A signup trigger creates the profile and grants `student` only.

**RLS** (enabled on every table):

- Public (anon + signed in): regions; countries/institutions where `is_public`; programmes/offerings where `is_published`; opportunities that are `published` and not sample data.
- Internal read (isc_team, doic_admin, leadership): everything above plus agreements, collaboration areas, documents, document links, activities, student profiles, applications.
- Writes: isc_team and doic_admin insert/update; deletes are doic_admin only. Leadership is read-only.
- Students: own profile (name only), own student profile, own applications (create for open published calls; no status changes), own notifications (mark read).
- `audit_logs`: written only by trigger; readable by doic_admin and leadership; no update/delete for any API role.

**Storage**: private bucket `institutional-documents` (25 MiB, PDF/Office/CSV/TXT/PNG/JPEG). Path `{entity_type}/{entity_uuid}/{filename}`, entity types `institutions|agreements|programs|program-availability|opportunities|activities|documents`. Read: internal roles. Upload/replace: isc_team, doic_admin. Delete: doic_admin.

**Seeds** (local only, loaded by `supabase db reset`): `01_reference.sql` (regions, countries, programmes from the public site), `02_directory.sql` (directory institutions, `data_source='directory'`, city/coordinates NULL because the directory only has the country hub city), `03_sample.sql` (fictional records, `data_source='sample'`, never public). Never run `supabase db push --include-seed` against a hosted project.

**App integration**: `src/lib/internal/data/context.ts` picks the dataset per request.

- `INTERNAL_DATA_SOURCE=static` (default, and what Vercel uses today): typed seeds, no env vars needed.
- `INTERNAL_DATA_SOURCE=supabase` + `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: reads Supabase as the signed-in user via `@supabase/ssr` (`src/lib/supabase/server.ts`). Rows map to the existing types using `slug`/`code` as ids, so URLs, filters, statuses, and reports are unchanged. Because there is no sign-in UI yet, RLS hides internal records from anonymous visitors: in this mode `/internal` shows only public directory rows and the existing empty/not-found states. Keep `static` until staff can sign in.
- `src/proxy.ts` refreshes the Supabase session on `/internal/*` only, and only in `supabase` mode.
- No service-role key is used anywhere in the app.

**Hosted project**: `isc-doic-muj-dashboard`, ref `oqmwrifysignwmgxiecd`, region `ap-south-1`, Postgres 17.

- All migrations are applied (`npx supabase migration list --linked`). No seeds are loaded: the hosted tables are empty apart from the four `roles` rows. Load verified DoIC data there, not the local seed files.
- The database password is not in the repo. `supabase link` / `db push` need `SUPABASE_DB_PASSWORD` (the original owner keeps it in the macOS Keychain, service `doic-supabase-db`).
- Auth: email sign-up with confirmation. Before staff sign-in ships, set Site URL and redirect URLs in the Supabase dashboard to the Vercel domain (`supabase/config.toml` only configures the local stack).
- Vercel (production and preview) has `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and `INTERNAL_DATA_SOURCE=static`.
- Verified against the hosted database: `rls.test.sql` (run with `psql` against the linked database; it rolls back), `supabase db lint --linked`, and `supabase db advisors --linked` (no security findings).

**First admin**: after the first staff account signs up, run in the Supabase SQL editor:

```sql
insert into public.user_roles (user_id, role)
select id, 'doic_admin' from auth.users where email = '<admin email>';
```

## Constraints

- Do not invent institutional data. Directory names are illustrative; sample records are fictional and marked `sample`.
- Directory coordinates are the country pin, not campus locations.
- Keep institutions, agreements, programmes, and programme availability as separate tables. Do not generate availability as a cross-product.
- RLS is the security boundary. Do not add service-role access to request paths.

## Device handoff

```bash
git clone https://github.com/FrostXMello/isc-doic-muj-dashboard.git
cd isc-doic-muj-dashboard
npm install
npm run dev
```

No environment variables are required. To work against a local database (needs Docker): `npx supabase start`, then `npx supabase db reset` (migrations + seeds) and `npx supabase test db`. Copy `.env.example` to `.env.local` for Supabase settings; never commit real values.
